## 1. 비용 절감 전략

### 결정사항

개발 환경에서 미사용 시간대에 EC2 및 RDS를 자동으로 정지/시작한다.

| 리소스 | 정지 | 시작 |
|--------|------|------|
| EC2 | 매일 03:00 KST | 매일 07:00 KST |
| RDS | 매일 03:00 KST | 매일 06:50 KST |

- EC2 스케줄: EventBridge Scheduler → EC2 API (`stopInstances` / `startInstances`)
- RDS 스케줄: EventBridge → Lambda (`rds_scheduler.py`) → RDS API

> 모니터링 모듈 작업 진행 중

## 2. 모니터링 및 알림

### CloudWatch 알람 (예정)

| 항목 | 임계값 | 대상 |
|------|--------|------|
| EC2 CPU | 80% 초과 | Backend EC2 |
| EC2 상태 체크 | 실패 감지 | Backend EC2 |
| RDS CPU | 80% 초과 | RDS |
| RDS 스토리지 | 2GB 미만 | RDS |
| RDS 연결 수 | 100 초과 | RDS |

### SNS 알림 (예정)

- CloudWatch 알람 및 EventBridge 상태 변경 이벤트를 SNS 토픽으로 수신한다.
- 이메일 구독을 통해 담당자에게 알림을 전달한다.

## 3. 접속 방법

### EC2 접속

SSH 키 없이 AWS Systems Manager Session Manager를 통해 접속한다.

```bash
aws ssm start-session --target <instance-id>
```

- EC2에 `AmazonSSMManagedInstanceCore` 정책이 부여되어 있어야 한다.
- Private 서브넷에 배치된 EC2도 NAT Gateway를 통해 SSM 엔드포인트에 접근 가능하다.
