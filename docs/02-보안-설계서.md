## 1. 네트워크 보안

### 보안그룹 구성

| 보안그룹 | 인바운드 | 허용 출처 |
|---------|---------|---------|
| ALB SG | 80, 443 | 0.0.0.0/0 (인터넷) |
| App SG | 8888 | ALB SG |
| DB SG | 3306 | App SG |

- ALB → EC2 → RDS 방향으로만 트래픽이 흐르도록 보안그룹을 체인 형태로 구성한다.
- RDS는 App SG에서 발생한 트래픽만 수신하며 인터넷 접근이 완전히 차단된다.

---

## 2. 전송 구간 암호화

### 결정사항

외부 트래픽은 전구간 HTTPS로 강제한다.

- ALB HTTP(80) 리스너는 HTTPS(443)로 301 리다이렉트한다.
- TLS 정책: `ELBSecurityPolicy-TLS13-1-2-2021-06` (TLS 1.3 우선)
- ACM 인증서는 DNS 검증 방식을 사용한다.

| 인증서 | 리전 | 용도 |
|--------|------|------|
| ACM (CloudFront) | us-east-1 | CloudFront HTTPS |
| ACM (ALB) | 배포 리전 | ALB HTTPS |

## 3. 인증 및 접근 제어

### EC2 IAM

- EC2 인스턴스에 IAM Role을 부여하여 자격증명을 코드에 하드코딩하지 않는다.
- 부여 정책:
  - `AmazonSSMManagedInstanceCore` — SSH 없이 Session Manager로 접속
  - `AmazonEC2ContainerRegistryReadOnly` — ECR 이미지 pull 전용

### S3 접근 제어

- 버킷 퍼블릭 액세스를 전면 차단한다 (4가지 옵션 모두 활성화).
- 프론트엔드 파일은 CloudFront를 통해서만 접근 가능하다.

## 4. 민감 정보 관리

- DB 자격증명(`MYSQL_USER`, `MYSQL_PASSWORD`)은 변수로 주입하며 `.tf` 파일에 하드코딩하지 않는다.
- `terraform.tfvars`는 `.gitignore`에 포함되어 형상관리에서 제외된다.
