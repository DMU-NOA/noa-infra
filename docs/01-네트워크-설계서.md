## 1. 전체 요청 흐름

### 결정사항

모든 트래픽은 인터넷 → ALB -> EC2 -> RDS 단방향 경로로 흐른다.

```
User
 └── ALB (HTTPS 443 / HTTP 80)
      └── /api/* → Backend EC2 (port 8888)
                        └── RDS MySQL (private subnet, port 3306)
```

---

## 2. VPC 구성

### 결정사항

Public / Private 서브넷을 분리하여 계층별 접근 제어를 적용한다.

| 서브넷 | 용도 | 인터넷 접근 |
|--------|------|------------|
| Public | ALB 배치 | IGW를 통해 직접 가능 |
| Private | Backend EC2, RDS 배치 | NAT Gateway를 통해 아웃바운드만 가능 |

### 결정 근거

- Backend EC2와 RDS를 Private 서브넷에 배치함으로써 인터넷 직접 노출을 차단한다.
- ALB는 Public 서브넷에 배치하여 외부 트래픽을 수신하고 Private의 EC2로 포워딩한다.
- Private EC2는 ECR 이미지 pull, 외부 API 호출 등 아웃바운드가 필요하므로 NAT Gateway를 사용한다.

### 트레이드오프

- NAT Gateway는 시간당 비용이 발생한다. 트래픽이 적은 개발 환경에서는 비용 부담이 있을 수 있다.

---

## 3. 주요 리소스 배치

```
VPC
├── Public Subnet (AZ-a, AZ-c)
│   ├── ALB
│   └── NAT Gateway (EIP 연결)
└── Private Subnet (AZ-a, AZ-c)
    ├── Backend EC2 (FastAPI, port 8888)
    └── RDS MySQL (port 3306)
```

---

## 4. 라우팅

| 라우트 테이블 | 대상 | 게이트웨이 |
|--------------|------|-----------|
| Public RT | 0.0.0.0/0 | Internet Gateway |
| Private RT | 0.0.0.0/0 | NAT Gateway |

## 5. 프론트엔드 전달 경로

정적 파일(React 빌드 결과물)은 S3에 업로드하고 CloudFront를 통해 제공한다.

```
User
 └── CloudFront
      └── S3 (정적 파일, 퍼블릭 직접 접근 차단)
```

- S3 버킷은 퍼블릭 액세스를 전면 차단하고 CloudFront OAC를 통해서만 접근 가능하다.
- CloudFront ACM 인증서는 us-east-1 리전에 프로비저닝한다 (CloudFront 요구사항).
