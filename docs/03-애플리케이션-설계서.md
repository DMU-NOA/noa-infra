## 1. 컴퓨팅 환경 선택

### 결정사항

EC2를 컴퓨팅 환경으로 선택한다.

### 결정 근거

- 소규모 프로젝트로 컨테이너 오케스트레이션(ECS, EKS) 도입 비용 대비 이점이 낮다.
- EC2에 직접 Docker 컨테이너를 실행하여 운영 복잡도를 줄인다.
- IAM Role + SSM Session Manager 조합으로 SSH 키 관리 없이 접속 가능하다.

### 트레이드오프

- 인스턴스 장애 시 자동 복구가 되지 않는다.

---

## 2. 서비스별 구성

### Backend (FastAPI)

| 항목 | 값 |
|------|-----|
| 런타임 | Python / FastAPI |
| 포트 | 8000 |
| 서브넷 | Private |
| 이미지 소스 | ECR |
| 헬스체크 경로 | `/api/health` |

### Frontend (React)

| 항목 | 값 |
|------|-----|
| 빌드 결과물 | S3 버킷 업로드 |
| 전달 방식 | CloudFront CDN |
| S3 접근 | CloudFront OAC 전용 (퍼블릭 차단) |
| 버전 관리 | S3 버킷 버저닝 활성화 |

### Database (RDS PostgreSQL)

| 항목 | 값 |
|------|-----|
| 엔진 | PostgreSQL |
| 스토리지 | 20GB gp2 |
| 서브넷 | Private |
| 공개 접근 | 차단 (`publicly_accessible = false`) |
| Multi-AZ | 기본 비활성화 (변수로 제어 가능) |

### Data Pipeline (`data-pipelines`, 배치)

| 항목 | 값 |
|------|-----|
| 런타임 | Python (`noa_data.jobs.*`) |
| 트리거 | EventBridge Scheduler (cron) |
| 컴퓨팅 | EC2 Spot (RunInstances), 작업 종료 시 자가 종료 |
| 서브넷 | Private |
| 스케줄 | 15분(실시간 수집) / 매일 01:10(전체 수집) / 매주 일(ML 재학습) |

상세 결정 근거는 5번 항목 참고.

---

## 3. ALB 라우팅 규칙

| 경로 | 대상 |
|------|------|
| 기본 (`*`) | Backend EC2 (port 8000) |

- `/api`, `/auth`, `/api/chat`, `/api/likes` 등은 전부 같은 포트(8000)의 FastAPI 앱이 내부적으로 라우팅하므로, ALB 단에서 경로별 규칙을 따로 둘 필요가 없다.
- Frontend는 CloudFront에서 직접 서빙하므로 ALB 라우팅 대상에 포함되지 않는다.

---

## 4. 컨테이너 이미지 관리

- ECR을 통해 Docker 이미지를 관리한다.
- EC2 IAM Role에 `AmazonEC2ContainerRegistryReadOnly` 정책을 부여하여 pull 가능하다.
- Private 서브넷의 EC2는 NAT Gateway를 통해 ECR 엔드포인트에 접근한다.

---

## 5. 데이터 파이프라인(`data-pipelines`) 컴퓨팅 환경 선택

### 결정사항

AWS Batch 대신 **EventBridge Scheduler + EC2 Spot(RunInstances)** 로 배치 작업을 실행하고, **Private 서브넷**에 배치한다.

### 결정 근거

- 스케줄(15분/매일/매주)대로 도는 단일 작업이라 Batch의 Job Queue·동시 스케일링이 불필요하다.
- 작업이 멱등하게 설계되어 있어, 스팟 중단 시 별도 재시도 없이 다음 스케줄이 이어받아 처리한다.
- EventBridge Scheduler가 EC2 `RunInstances`를 범용 타겟으로 지원해, Batch의 컨테이너화·Compute Environment 없이도 스케줄 실행이 가능하다.
- 배치 작업은 외부 API 호출(아웃바운드)만 필요하고 인바운드는 불필요하므로 Private 서브넷 + NAT Gateway로 충분하다.
- RDS와 같은 VPC의 Private 서브넷에 있어 NAT를 거치지 않고 내부 라우팅된다.

### 트레이드오프

- 성공/실패 감지 및 인스턴스 자가 종료(self-terminate) 로직을 직접 구현해야 한다.
- 스팟 중단 시 즉시 재시도가 없어, 영구 실패(예: API 키 만료)는 별도 모니터링으로 감지해야 한다.
- NAT Gateway는 처리 데이터량(GB) 기준 과금도 있어, 트래픽이 누적되면 비용이 커질 수 있다.
