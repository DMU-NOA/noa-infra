## 1. 컴퓨팅 환경 선택

### 결정사항

EC2를 컴퓨팅 환경으로 선택한다.

### 결정 근거

- 소규모 프로젝트로 컨테이너 오케스트레이션(ECS, EKS) 도입 비용 대비 이점이 낮다.
- EC2에 직접 Docker 컨테이너를 실행하여 운영 복잡도를 줄인다.
- IAM Role + SSM Session Manager 조합으로 SSH 키 관리 없이 접속 가능하다.

### 트레이드오프

- Auto Scaling이 없어 트래픽 급증 시 수동 대응이 필요하다.
- 인스턴스 장애 시 자동 복구가 되지 않는다.

## 2. 서비스별 구성

### Backend (FastAPI)

| 항목 | 값 |
|------|-----|
| 런타임 | Python / FastAPI |
| 포트 | 8888 |
| 서브넷 | Private |
| 이미지 소스 | ECR |
| 헬스체크 경로 | `/api/health` |

### Frontend (React)

| 항목 | 값 |
|------|-----|
| 빌드 결과물 | S3 버킷 업로드 |
| 전달 방식 | CloudFront CDN |
| S3 접근 | CloudFront OAC 전용 (퍼블릭 차단) |
| 버전 관리 | S3 버킷 버저닝 활성화 |

### Database (RDS MySQL)

| 항목 | 값 |
|------|-----|
| 엔진 | MySQL |
| 스토리지 | 20GB gp2 |
| 서브넷 | Private |
| 공개 접근 | 차단 (`publicly_accessible = false`) |
| Multi-AZ | 기본 비활성화 (변수로 제어 가능) |

---

## 3. ALB 라우팅 규칙

| 경로 | 대상 |
|------|------|
| 기본 (`*`) | Backend EC2 (port 8888) |

- Frontend는 CloudFront에서 직접 서빙하므로 ALB 라우팅 대상에 포함되지 않는다.

---

## 4. 컨테이너 이미지 관리

- ECR을 통해 Docker 이미지를 관리한다.
- EC2 IAM Role에 `AmazonEC2ContainerRegistryReadOnly` 정책을 부여하여 pull 가능하다.
- Private 서브넷의 EC2는 NAT Gateway를 통해 ECR 엔드포인트에 접근한다.
